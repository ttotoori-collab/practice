# 손글씨 숫자 인식기 — 웹/데스크톱 버전 분리 설계

작성일: 2026-09-26 (KST)

## 1. 배경과 목표

현재 저장소는 tkinter 데스크톱 앱 하나로 이루어져 있다. 이를 두 갈래로 나눈다.

- `desktop_version/` — 기존 코드를 그대로 옮긴 것. PyTorch 추론, tkinter GUI, Windows 바로가기.
- `web_version/` — 새로 작성. **외부 라이브러리 없는 순수 자바스크립트**로 추론하고,
  GitHub Pages 에 정적 파일만 올려 동작해야 한다.

학습(`train.py`)은 데스크톱 쪽에만 둔다. 웹은 학습된 가중치를 소비하는 쪽이다.

## 2. 합의된 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 가중치 전달 형식 | Float32 리틀엔디언 바이너리 + JSON 목록 | 데스크톱과 수치가 완전히 동일. 1.7MB 는 Pages 에 부담 없음 |
| 웹 기능 범위 | 데스크톱 동등 + 터치 입력 + 반응형 | YAGNI. 웹에서만 의미 있는 것은 터치/반응형뿐 |
| 재학습 | 하지 않음 | 기존 `mnist_cnn.pt` 를 그대로 변환 |
| 축소 필터 | Lanczos3 를 JS 로 직접 구현 | canvas `drawImage` 는 브라우저마다 결과가 달라 인식률이 흔들린다 |
| 식별자 규약 | 웹도 한글 식별자·주석 | 저장소 전체 규약 유지 |
| 검증 기준 | MNIST 평가 200장을 웹 경로에 통과, 190/200 이상 | 데스크톱과 같은 기준 |
| 배포 | GitHub Actions 로 `web_version/` 을 Pages 에 업로드 | Pages 는 하위 폴더를 직접 지목할 수 없다 |

## 4. 웹 버전 아키텍처

다섯 개 ES 모듈. 각각 하나의 책임만 지고, 브라우저 API 의존을 한쪽으로 몰아 둔다.

### 4.1 `js/가중치.js` — 가중치 로더

`모델/mnist_cnn.json` (텐서 이름·모양·바이트 오프셋 목록) 과 `모델/mnist_cnn.bin` 을
`fetch` 로 받아 `{이름: {모양, 값:Float32Array}}` 형태로 돌려준다.
바이너리 형식은 PyTorch `state_dict` 의 텐서를 C 순서(행 우선)로 이어 붙인 것이다.

의존: `fetch` 뿐. 순수 데이터 변환.

### 4.2 `js/신경망.js` — 추론 엔진

`model.py` 의 `숫자인식CNN` 순전파를 그대로 옮긴다. 브라우저 API 를 쓰지 않는
순수 함수 묶음이라 단위 검증이 쉽다.

- `합성곱(입력, 가중치, 편향, 입력채널, 출력채널, 크기, 여백)` — padding=1, stride=1
- `최대풀링(입력, 채널, 크기)` — 2×2
- `렐루(배열)`, `전결합(입력, 가중치, 편향, 입력수, 출력수)`
- `로그소프트맥스(배열)` → 최댓값을 빼는 안정화 포함
- `추론(입력28x28, 가중치)` → 길이 10 확률 배열

드롭아웃은 평가 모드에서 항등 함수이므로 구현하지 않는다.
평탄화 순서는 PyTorch `flatten(1)` 과 같은 (채널, 높이, 너비) 순서:
`색인 = 채널*49 + 행*7 + 열`. 이 순서가 어긋나면 전결합1 가중치와 맞지 않는다.

연산량은 약 420만 MAC 으로, 브라우저에서 10ms 안에 끝난다. 최적화는 하지 않는다.

### 4.3 `js/전처리.js` — MNIST 정규화 절차

`app.py` 의 `전처리()` 를 픽셀 단위로 재현한다. 인식률의 핵심이므로 절차를 바꾸지 않는다.

1. `경계상자()` — 0 이 아닌 픽셀의 사각 범위. 없으면 `null` (아무것도 안 그린 상태)
2. `잘라내기()` — 경계상자로 crop
3. `란초스축소()` — 긴 변이 20px 이 되도록 비율 유지 축소.
   PIL `Image.resize(..., LANCZOS)` 의 알고리즘을 그대로 구현한다:
   축소 시 `필터배율 = max(1, 원본크기/결과크기)`, `지지폭 = 3*필터배율`,
   중심 `= (출력색인+0.5)*배율`, 가중치 `= 란초스((x-중심+0.5)/필터배율)`,
   가중치 합으로 정규화, 가로·세로를 분리 적용, 마지막에 반올림 후 0~255 로 자름.
4. `중앙배치()` — 28×28 검은 도화지 가운데에 붙인다 (`(28-너비)>>1`)
5. `무게중심이동()` — 픽셀 무게중심을 (13.5, 13.5) 로. 이동량은 정수 반올림,
   빈 자리는 0 으로 채우는 최근접 평행이동 (PIL AFFINE + NEAREST 와 동일)
6. `정규화()` — `(값/255 - 0.1307) / 0.3081`

`평균 = 0.1307`, `표준편차 = 0.3081` 은 `train.py`·`app.py` 와 같은 값이어야 한다.

### 4.4 `js/그림판.js` — 캔버스 입력

280×280 캔버스에 검은 배경 + 흰 붓(굵기 22)으로 그린다. 데스크톱과 같은 값이다.

데스크톱은 화면용 tkinter Canvas 와 인식용 PIL Image 에 이중으로 그렸다.
웹은 canvas 픽셀을 `getImageData` 로 되읽을 수 있으므로 **캔버스 하나만 쓴다.**
`lineCap`/`lineJoin` 을 `round` 로 두면 tkinter 의 `capstyle=ROUND` 와 같은 모양이 된다.

CSS 로 크기를 줄여 표시해도 내부 해상도는 280×280 으로 고정한다 (반응형).
포인터 이벤트(`pointerdown`/`move`/`up`)를 쓰면 마우스·터치·펜이 한 경로로 처리된다.
`touch-action: none` 으로 스크롤 제스처와의 충돌을 막는다.

### 4.5 `js/앱.js` — 조립

가중치 로드 → 그림판 준비 → 붓을 떼면 인식 → 결과 숫자·확신도·0~9 확률 막대 갱신.
데스크톱의 `손글씨앱` 클래스와 같은 화면 구성을 따른다.

## 5. 도구와 검증

### 5.1 `도구/가중치_내보내기.py`

`desktop_version/mnist_cnn.pt` 를 읽어 `web_version/모델/` 에 `.bin` + `.json` 을 쓴다.
PyTorch 가 필요하므로 데스크톱 환경에서 실행하는 빌드 도구다. 웹 실행에는 쓰이지 않는다.
모델 구조를 바꾸면 이 스크립트를 다시 돌려야 한다.

### 5.2 `검증/검증.html`

MNIST 평가 이미지 200장을 `도구/평가데이터_만들기.py` 로 뽑아
`검증/평가데이터.bin` (200×784 바이트 + 라벨 200바이트) 에 담는다.
검증 페이지는 각 28×28 이미지를 280×280 으로 확대(데스크톱 검증 절차와 동일)한 뒤
웹 전처리·추론 경로에 그대로 통과시켜 맞힌 개수를 표시한다.

**합격 기준: 190/200 이상.** 데스크톱 CLAUDE.md 의 검증 기준과 같다.

가중치가 데스크톱과 동일하므로, 이 수치가 낮으면 원인은 전처리 또는 평탄화 순서다.

## 6. 배포

`.github/workflows/pages.yml` 이 `web_version/` 을 그대로 Pages 아티팩트로 올린다.
빌드 단계는 없다. 저장소 설정에서 Pages 소스를 "GitHub Actions" 로 두어야 동작한다.

`.bin` 파일 경로는 상대 경로만 쓰므로 `user.github.io/저장소이름/` 하위에서도 동작한다.

## 7. 두 버전이 맞춰야 하는 값

어긋나면 조용히 인식률만 떨어지는 값들이다.

- 정규화 상수 `0.1307` / `0.3081` — `train.py`, `app.py`, `js/전처리.js`
- 전처리 절차 6단계 — `app.py` 의 `전처리()`, `js/전처리.js`
- 모델 구조 — `model.py`, `js/신경망.js`, 그리고 `mnist_cnn.bin`
- 캔버스 280 / 펜 굵기 22 — `app.py`, `js/그림판.js`

## 8. 범위에서 뺀 것

- 웹에서의 학습·재학습 (브라우저에서 학습할 이유가 없다)
- WebGL/WebGPU 가속 (420만 MAC 에는 불필요)
- 실시간 인식, 전처리 미리보기, 그리기 취소 (YAGNI)
- 모델 구조 변경, 양자화
