# CLAUDE.md — 웹 버전

브라우저에서 손글씨 숫자를 인식하는 웹 앱. **외부 라이브러리가 하나도 없다.**
빌드 도구도, 번들러도, 패키지 매니저도 쓰지 않는다. 정적 파일을 그대로 서빙하면 끝이다.

가중치는 `desktop_version` 에서 학습한 `mnist_cnn.pt` 를 변환해서 쓴다.
**이 폴더에서 학습하지 않는다.** 학습은 데스크톱 쪽 책임이다.

저장소 전체 규약은 뿌리의 [CLAUDE.md](../CLAUDE.md) 를 함께 본다.

## 명령어

```bash
# 로컬에서 띄우기 (file:// 로 열면 fetch 가 막혀서 모델을 못 읽는다)
python -m http.server 8765 --directory web_version    # 저장소 뿌리에서
# http://localhost:8765/ 접속

# 가중치를 다시 내보내기 (desktop_version 에서 재학습한 뒤에 필요)
python web_version/도구/가중치_내보내기.py

# 검증용 MNIST 평가 이미지 다시 뽑기 (보통 다시 할 일이 없다)
python web_version/도구/평가데이터_만들기.py
```

`도구/` 의 두 스크립트만 파이썬과 PyTorch 가 필요하다. 웹 앱 자체는 브라우저만 있으면 된다.

## 변경 후 검증하는 법

**전처리나 신경망을 건드렸으면 반드시 `검증/검증.html` 을 열어 본다.**

```
http://localhost:8765/검증/검증.html
```

MNIST 평가 이미지 200장을 앱이 실제로 쓰는 모듈(`js/전처리.js`, `js/신경망.js`)에
그대로 통과시켜 정확도를 잰다. **합격 기준은 190/200 이상**이고, 현재 199/200 이다.
데스크톱 버전도 같은 200장에서 199/200 이며 틀리는 이미지(43번)까지 같다.

숫자가 떨어졌으면 원인은 거의 항상 둘 중 하나다.

- `js/전처리.js` 의 6단계 중 하나가 `app.py` 의 `전처리()` 와 어긋남
- `js/신경망.js` 의 평탄화 순서가 `(채널, 행, 열)` 이 아니게 됨

가중치는 데스크톱과 같은 수치이므로, 가중치를 의심하는 것은 대개 헛수고다.

## 구조

```
index.html        화면 뼈대
스타일.css        데스크톱 버전과 같은 배색
js/가중치.js      모델/*.bin, *.json 을 fetch 해서 이름으로 찾아 쓰게 정리
js/신경망.js      CNN 순전파. 브라우저 API 를 쓰지 않는 순수 함수만
js/전처리.js      그림 → 28x28 MNIST 형식. Lanczos3 리샘플링 포함
js/그림판.js      캔버스 입력 (포인터 이벤트로 마우스·터치·펜 한 번에)
js/앱.js          위 넷을 조립하고 화면을 갱신
모델/             가중치_내보내기.py 가 만든 결과물. 손으로 고치지 않는다
도구/             .pt → .bin 변환, 평가 데이터 추출 (파이썬)
검증/             검증.html + 평가데이터.bin
```

ES 모듈(`<script type="module">`)을 쓴다. 그래서 파일을 나눠도 번들러가 필요 없다.

## 알아 둘 점

**`js/전처리.js` 가 인식률의 핵심이다.** `app.py` 의 `전처리()` 와 같은 6단계를
같은 순서로 밟는다. 단순화하면 정확도가 떨어진다.

**축소를 canvas 의 `drawImage` 에 맡기지 않는다.** `drawImage` 의 리샘플링
알고리즘은 명세에 정해져 있지 않아 브라우저마다 결과가 다르고, PIL 의 LANCZOS 와도
어긋나 데스크톱과 인식 결과가 달라진다. 그래서 Lanczos3 를 `js/전처리.js` 안에
직접 구현했다. PIL 의 `Image.resize` 계산 절차(필터 폭을 축소 배율만큼 넓히고,
가중치 합으로 정규화하고, 축마다 0~255 로 자르는 것)를 그대로 따른다.
실제로 두 구현의 전처리 결과는 156,800 픽셀 중 10 픽셀만 1/255 만큼 다르다.

**`파이썬반올림()` 이 따로 있는 이유.** 자바스크립트 `Math.round` 는 0.5 를 항상
위로 올리지만 파이썬 `round()` 는 짝수 쪽으로 보낸다. 축소 크기와 무게중심 이동량
계산에서 값이 어긋나면 1픽셀씩 밀리므로 파이썬 규칙을 따라 구현했다.

**캔버스는 하나만 쓴다.** 데스크톱은 tkinter Canvas 에서 픽셀을 되읽을 수 없어
PIL 이미지에 이중으로 그렸지만, 웹은 `getImageData` 로 읽을 수 있다.
데스크톱 코드를 참고하다가 이중 그리기를 따라 옮기지 않도록 주의한다.

**캔버스 내부 해상도는 항상 280×280 이다.** CSS 로 표시 크기만 줄인다.
화면 크기에 따라 전처리 결과가 달라지면 안 되기 때문이다.
좌표 변환은 `그림판.js` 의 `좌표변환()` 이 `getBoundingClientRect` 비율로 처리한다.

**`모델/mnist_cnn.bin` 은 Float32 리틀엔디언이다.** `Float32Array` 로 버퍼를
그대로 해석하므로 빅엔디언 기기에서는 값이 깨진다. 실제로 쓰이는 브라우저 환경은
모두 리틀엔디언이라 변환 코드를 넣지 않았다.

## 코드 규약

저장소 규약대로 **식별자와 주석이 모두 한글이다.** 자바스크립트는 유니코드 식별자를
허용하므로 함수·변수·클래스 이름을 한글로 쓴다. CSS 클래스 이름도 마찬가지다.

예외는 두 군데다. 둘 다 언어·플랫폼이 한글을 못 받는 자리다.

- `js/` 안의 DOM API 이름 (`getImageData`, `addEventListener` 등) — 표준 API 이름
- `.github/workflows/pages.yml` 의 job·step `id` — GitHub 가 영문·숫자만 받는다
